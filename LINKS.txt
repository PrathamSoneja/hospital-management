1. PUBLIC WEB SERVICE (Patient Registry on GKE, behind a Google Cloud HTTP load balancer)
================================================================================
Interactive API page (try the API in a browser) : http://35.244.157.132/docs
OpenAPI specification (JSON)                    : http://35.244.157.132/openapi.json
Health check                                    : http://35.244.157.132/healthz

REST API base                                   : http://35.244.157.132/api/v1
  POST /api/v1/patients                                  create a patient
  GET  /api/v1/patients/{patient_id}                     read a patient
  POST /api/v1/admissions                                open an admission for a patient
  GET  /api/v1/admissions/{admission_id}                 read an admission
  POST /api/v1/patients/{patient_id}/documents           upload a PDF/JPEG/PNG (stored in Cloud Storage)
  GET  /api/v1/patients/{patient_id}/documents/{doc_id}  download a stored document

Notes:
  - Every POST needs an "Idempotency-Key" header (any unique string, 1-128 characters); /docs shows the field.
    Repeating a request with the same key returns the original result; the same key with a different body
    returns 409 IDEMPOTENCY_MISMATCH.
  - Use synthetic data only.
  - Plain HTTP. The IP stays the same while the Ingress exists; it changes only if the Ingress is recreated.
  - /metrics and /readyz are intentionally not exposed (they return 404).

--------------------------------------------------------------------------------
1a. REQUEST AND RESPONSE FORMATS (from http://35.244.157.132/openapi.json)
--------------------------------------------------------------------------------
All bodies are JSON (Content-Type: application/json) except the document upload (multipart/form-data).
IDs are generated by the service: patients "pat-<32 hex>", admissions "adm-<32 hex>", documents "doc-<32 hex>".
Timestamps are ISO-8601 UTC; dates are YYYY-MM-DD.

GET /healthz
  Response 200:
    {"status": "ok", "service": "patient-registry"}

POST /api/v1/patients                          (header: Idempotency-Key)
  Request body:
    {
      "first_name": "Synthetic",            required, 1-100 characters
      "last_name": "Patient",               required, 1-100 characters
      "date_of_birth": "1990-01-01",        required, YYYY-MM-DD
      "phone": null                         optional, string up to 32 characters, or null
    }
  Response 201:
    {
      "patient_id": "pat-21c8906449b645ea99ba51e7bc23b547",
      "first_name": "Synthetic",
      "last_name": "Patient",
      "date_of_birth": "1990-01-01",
      "phone": null,
      "created_at": "2026-11-16T15:42:53.583294Z"
    }

GET /api/v1/patients/{patient_id}
  Response 200: same shape as the POST response above.

POST /api/v1/admissions                        (header: Idempotency-Key)
  Request body:
    {"patient_id": "pat-21c8906449b645ea99ba51e7bc23b547"}     required, existing patient, up to 64 characters
  Response 201:
    {
      "admission_id": "adm-4a436c8f29444f2aad9648bbe959ddde",
      "patient_id": "pat-21c8906449b645ea99ba51e7bc23b547",
      "status": "OPEN",                     one of OPEN, DISCHARGED, CANCELLED
      "admitted_at": "2026-11-16T15:42:54.958694Z",
      "discharged_at": null
    }

GET /api/v1/admissions/{admission_id}
  Response 200: same shape as the POST response above.

POST /api/v1/patients/{patient_id}/documents   (header: Idempotency-Key; multipart/form-data)
  Form fields:
    document_type = REFERRAL_LETTER | ID_SCAN       required
    file          = the file                          required; PDF, JPEG or PNG, at most 10 MiB
  Response 201:
    {
      "document_id": "doc-7994aa08d33246d98d973fc5eddb6835",
      "patient_id": "pat-21c8906449b645ea99ba51e7bc23b547",
      "document_type": "REFERRAL_LETTER",
      "content_type": "application/pdf",
      "size_bytes": 71,
      "uploaded_at": "2026-11-16T15:46:49.465233Z"
    }
  The file is stored in Cloud Storage (gs://hospital-patient-docs-514618/patient-documents/<document_id>.<ext>).

GET /api/v1/patients/{patient_id}/documents/{document_id}
  Response 200: the file itself, with its original content type (application/pdf, image/jpeg or image/png).

Errors (every endpoint) use one envelope:
    {"error": {"code": "NOT_FOUND", "message": "Patient was not found", "request_id": "req-4ffb03a41176",
               "retryable": false}}
  Codes: 400 INVALID_ARGUMENT (bad body or missing Idempotency-Key), 404 NOT_FOUND,
         409 IDEMPOTENCY_MISMATCH / STATE_CONFLICT, 503 SERVICE_UNAVAILABLE (retryable).

Example with curl (any shell):
  curl -X POST http://35.244.157.132/api/v1/patients \
       -H "Content-Type: application/json" -H "Idempotency-Key: demo-patient-1" \
       -d '{"first_name":"Synthetic","last_name":"Patient","date_of_birth":"1990-01-01"}'
  curl -X POST http://35.244.157.132/api/v1/admissions \
       -H "Content-Type: application/json" -H "Idempotency-Key: demo-admission-1" \
       -d '{"patient_id":"<patient_id from the previous response>"}'
  curl -X POST http://35.244.157.132/api/v1/patients/<patient_id>/documents \
       -H "Idempotency-Key: demo-document-1" \
       -F "document_type=REFERRAL_LETTER" -F "file=@letter.pdf;type=application/pdf"

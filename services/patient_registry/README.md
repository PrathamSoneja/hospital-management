# Patient Registry

The Patient Registry owns the `patients` Cloud SQL PostgreSQL database and the private patient-document bucket. It exposes REST on port `8000`; all application configuration is provided through environment variables.

## Configuration

- `PATIENT_REGISTRY_DATABASE_URL`: SQLAlchemy PostgreSQL URL pointing at the `patients` database. In GKE, use the Cloud SQL private IP, `sslmode=require`, and the dedicated database user delivered through the approved secret mechanism.
- `PATIENT_DOCUMENTS_BUCKET`: bucket name provisioned by Terraform.
- `GCP_PROJECT_ID`: optional explicit project for the Storage client; GKE Workload Identity is used for credentials.
- `PATIENT_REGISTRY_REST_HOST`: bind address, default `0.0.0.0`.
- `PATIENT_REGISTRY_REST_PORT`: REST port, default `8000`.

The service does not create database tables on production startup. Apply its Alembic migration against the `patients` database using the Cloud SQL administrator login before deploying a new version. The migration grants the Terraform-provisioned `patient_registry` role access to its tables; run the application with that least-privilege role:

```text
alembic -c services/patient_registry/alembic.ini upgrade head
```

Set `PATIENT_REGISTRY_DATABASE_URL` for the migration process to the administrator URL, and set it to the `patient_registry` login for the service runtime. Supply passwords through the approved secret injection mechanism. This is a migration job/task, not a Kubernetes application deployment.

## REST endpoints

- `POST /api/v1/patients` creates a patient; requires `Idempotency-Key`.
- `GET /api/v1/patients/{patient_id}` fetches a patient.
- `POST /api/v1/admissions` creates an `OPEN` admission; requires `Idempotency-Key`.
- `GET /api/v1/admissions/{admission_id}` returns `admission_id`, `patient_id`, and `status` for Bed Allocation compatibility.
- `POST /api/v1/patients/{patient_id}/documents` uploads a multipart `file` and `document_type` (`REFERRAL_LETTER` or `ID_SCAN`); requires `Idempotency-Key`.
- `GET /api/v1/patients/{patient_id}/documents/{document_id}` retrieves a private document.

Uploads accept PDF, JPEG, or PNG content up to 10 MiB. Object names are generated by the service; original filenames and document bytes are not written to application logs. Bucket-level public access is disabled by Terraform.

All errors use the shared JSON error envelope and responses carry `X-Request-ID`. Liveness and readiness endpoints are `/healthz` and `/readyz`.

For local unit tests, inject an in-memory SQLite engine and a test `DocumentStorage`; production must use Cloud SQL and Google Cloud Storage.
